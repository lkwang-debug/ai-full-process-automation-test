# fm_client 业务层设计文档（测试人员向）

> 本文档面向**自动化测试人员**，说明 4u 会议业务层（`fm_client`）的**设计思路、方案选型、调用方式**。
> 不涉及底层会话层（`framecore_session`）的内部实现——那层负责 TCP 可靠传输/握手/加密/重连，业务层和测试代码都不用关心。

---

## 一、你在哪一层

```
┌─────────────────────────────────────────────────────────┐
│  你的测试代码  (tests/test_*.py)                          │  ← 你写这里
├─────────────────────────────────────────────────────────┤
│  fm_client 业务层                                         │  ← 本文档
│   ├─ FmTestClient   测试糖衣：typed 返回 + 等推送 + fixture │  ← 你主要用这个
│   └─ FmClient       协议门面：1:1 映射会议命令，raw dict   │  ← 生产/开发用
├─────────────────────────────────────────────────────────┤
│  framecore_session 会话层（传输：TCP/握手/序号/ACK/重连）   │  ← 不展开
├─────────────────────────────────────────────────────────┤
│  4u_fmserver  真实会议服务器（C++）                        │
└─────────────────────────────────────────────────────────┘
```

**一句话**：测试人员只接触 `fm_client`，绝大多数情况用 `FmTestClient`。会话层是黑盒，业务层帮你把"发一条 XML 命令、等回复、收推送"全部封装成了普通方法调用。

## 二、设计思路与方案选型

### 2.1 为什么有两个客户端（`FmClient` / `FmTestClient`）

| | `FmClient`（协议门面） | `FmTestClient`（测试糖衣） |
|---|---|---|
| 定位 | 生产/开发用，1:1 映射协议 | 自动化测试用 |
| 返回值 | **raw dict + 字符串值**（贴近线缆） | **typed 对象**（`Room`/`Contact`/...，int 字段） |
| 异步推送 | 裸 `FmListener` 回调（接收线程） | `EventCollector` 收集 + `wait_for_*` |
| 谁继承谁 | 基类 | `FmTestClient(FmClient)`，继承全部能力 |

**为什么不直接把 `FmClient` 做成 typed？** —— 职责分离。协议门面要**稳定、贴近协议、轻**（字段名/类型跟服务端 XML 一一对应，方便排查线缆问题）；测试糖衣要**好断言**（int 字段、等事件、fixture）。两层各自演进，互不干扰。你写测试用 `FmTestClient`，开发排查问题看 `FmClient`。

### 2.2 `FmClient` 内部怎么组织 —— 平铺 Mixin 方案

按你的要求"**对接不同服务/功能放独立类，共享数据和对外接口放 `FmClient`**"，采用**平铺 Mixin**：

```
FmClient (client.py)                  ← 共享数据 + 会话机械 + 对外接口
  ├─ 共享状态：_front/_conf 会话、local_user_id、room_id、token、room_srv_node_id ...
  ├─ 核心机械：_request / _send / _connect / _ensure_front / _ensure_conf / _dispatch_push / close
  └─ 继承以下 mixin（各功能的方法定义在这些独立类里）：
        FrontOps     (ops/front_ops.py)      登录 / 加入会议变体 / 列表 / 发现 / 注销
        ConfOps      (ops/conf_ops.py)       会中控场（聊天/音视频/录制/主席/踢人/静音）
        ContactsOps  (ops/contacts_ops.py)   通讯录查询（离线成员/组织架构/配置/快照）
        CallOps      (ops/call_ops.py)       通讯录邀请（呼叫电话/H323 入会）
        MeetingOps   (ops/meeting_ops.py)    扩展会议控制（分组/操作权/字幕/改名/撤回/视图）
        EntranceOps  (ops/entrance_ops.py)   Entrance 配置下发
```

**选型对比**（当初二选一）：

| 方案 | 调用形态 | 选用？ |
|---|---|---|
| **平铺 Mixin**（采用） | `client.front_login(...)` / `client.conf_invite_call(...)` —— 方法直接挂在 `FmClient` 上 | ✅ 对外 API 统一、好记；测试零模板 |
| 命名空间委托 | `client.front.login(...)` / `client.call.invite(...)` —— 各服务是独立对象挂在 client 下 | ✗ 调用方要改、多一层 |

**结论**：`class FmClient(FrontOps, ConfOps, ContactsOps, CallOps, MeetingOps, EntranceOps)`。
每个 mixin 只定义本域方法，靠 `self.*` 复用 `FmClient` 的共享状态和 `_request/_send`。**对外就是 `client.方法名()`**，功能内聚到各自文件。

> 注：4u 真正的"服务"按 `application_id` 分是 3 个：Entrance(app=8)/Front(app=20)/Conf(app=11)。
> 其中 Conf 一个服务按**功能**再拆成了 4 个 mixin（ConfOps/ContactsOps/CallOps/MeetingOps），它们共用同一条 conf 会话，目的是文件内聚、好维护。

### 2.3 同步请求 + 异步推送模型

业务命令分两类，调用语义不同：

- **请求-回复型**（如 `front_login`、`conf_invite_call`）：**方法阻塞等回复**，带超时（默认 8s）。调完拿到结果 dict 就能断言。回复 `Result != 0` 默认抛 `FmError`（带错误码）。
- **通知-广播型**（如 `mic_on`、`chat`、`set_subtitle`）：**发送即返回**（不等回复）。服务器会把状态变化**推送**给全体（包括你自己），推送走 `FmListener` 回调。

推送在**会话接收线程**触发——这就是为什么裸 `FmClient` 测试要自己写线程安全的捕获代码。`FmTestClient` 的 `EventCollector` 帮你做了这层：收集所有推送 + 提供 `wait_for_xxx(timeout)`，你在测试线程直接等。

## 三、测试人员怎么调用（核心）

### 3.1 离线测试（mock，推荐先用）

用 `conftest.py` 提供的 `fm` fixture（自动连 mock、自动清理）：

```python
def test_mic_on_broadcasts_state(fm):        # fm = 连着 mock 的 FmTestClient
    fm.front_login("guest1", "1111", room_id=100001, room_node_id="1")
    fm.conf_login(user_name="guest1")
    fm.mic_on()
    # 等服务器广播的 6609 状态变更（typed，UserID 已 int 化）
    states = fm.wait_for_user_state(timeout=3)
    assert any(isinstance(s.get("Audio"), dict) for s in states)
```

> `fm` fixture 跑在内置 `MockFmServer` 上，不依赖真实服务器，CI 里随时跑。

### 3.2 真机测试

把 `FmTestClient` 直连真实服务器（用法和 mock 完全一样，只换地址）：

```python
from fm_client import FmTestClient

client = FmTestClient(
    "192.168.7.154", 1089,
    request_timeout=8.0,
    conf_protocol_version="2.0",
)
try:
    client.front_login("A7", "<configure-locally>", room_id=10000, room_node_id="396593")
    client.conf_login(user_name="A7")
    client.mic_on()
    assert client.wait_for_user_state(timeout=5)
finally:
    client.close()
```

### 3.3 最小完整流程（login → 入会 → 操作 → 断言推送 → 退出）

```python
from fm_client import FmTestClient, conf as C

client = FmTestClient("192.168.7.154", 1089)
try:
    # 1) 加入会议（USERLOGIN + LOGINROOM，阻塞等回复）
    client.front_login("A7", "<configure-locally>", room_id=10000, room_node_id="396593")
    assert client.user_right_int == 3            # 主席（int，不用 int("3")）

    # 2) 进入会场（LOGINREQ → 收 6601 → 发 INITCOMPLETE）
    client.conf_login(user_name="A7")

    # 3) 收已有成员的入会推送（6602，typed UserEnter）
    members = client.wait_for_user_enter(timeout=5)
    assert all(m.right in (1, 2, 3) for m in members)

    # 4) 做动作 + 等广播
    client.chat("hello")
    assert client.wait_for_chat(text="hello", timeout=3)

    client.start_record()
    assert client.wait_for_recording_state(C.RECORD_RECORDING, timeout=3)  # =2

    # 5) 退出
    client.conf_logout()
    client.front_logout()
finally:
    client.close()
```

## 四、API 速查（按功能分组）

> 全部方法都在 `FmTestClient`（继承自 `FmClient`）上，`client.xxx()` 直接调。
> 下表"返回"列：`dict`=协议回复字段；`typed`=`FmTestClient` 包装的对象；`None`=通知型（发送即返回，结果看推送）。

## 五、推送事件与 `wait_for_*`

服务器主动推的状态变化，由 `EventCollector` 收集。**你不用实现监听器，直接等**：

| 业务事件 | cmdid | typed/便捷等待 |
|---|---|---|
| 成员入会/在线列表 | 6602 | `wait_for_user_enter(user_id=None, timeout)` → `List[UserEnter]` |
| 成员离开 | 6605 | `wait_for_user_leave(user_id=None, timeout)` |
| 成员状态变更（开麦/摄像头/Right） | 6609 | `wait_for_user_state(user_id=None, timeout)` → `List[dict]` |
| 聊天消息 | 6612 | `wait_for_chat(text=None, src=None, timeout)` → `List[ChatMsg]` |
| 会议状态/录制状态 | 6610 | `wait_for_recording_state(state, timeout)` / `wait_for_conf_state(timeout)` |
| 呼叫状态（邀请后） | 6745 | `wait_for_call_state(call_state=None, timeout)` |
| 字幕 | 6615 | `wait_for_subtitle(text=None, timeout)` |
| 敲门 | 6604 | `wait_for_knock(user_id=None, timeout)` |
| 被踢（含当前 HTTP `USER_REMOVE`） | 6606 | `events.wait_for_kicked(user_id=None, timeout)`；HTTP 来源 `KickID=-2` |
| 收文件 | 6616 | `wait_for_send_file(timeout)` |
| 连接建立 | — | `wait_front_connected(timeout)` / `wait_conf_connected(timeout)` |
| 系统消息/分组切换/字幕关闭 | 6618/6624/6626/6650 | `system_messages` / `group_enters` / `main_enters` / `subtitle_closes` |
| 会场数据/视频字幕/聊天审批 | 6619/6622/6629 | `room_data_updates` / `video_subtitles` / `chat_check_results` |
| 角色/用户权限变更 | 6632/6635 | `role_permission_changes` / `user_permission_changes` |
| 系统通知/组播状态 | 6636/6651 | `system_notifies` / `multicast_states`兼容解析；6636仅主服务器到节点，6651当前代码未实现，终端测试不执行 |
| 人脸点名/中转消息 | 6657/6658/6659/6700 | `face_rollcall_*` / `relay_messages` |
| 其它（踢人/静音/撤回/角色权限/视图…） | 6606/6614/6669/6631/6613… | `client.events.<deque名>` + `snapshot()` / `wait_until(pred)` |

> 当前产品约定：Conf `6506` 和 HTTP `USER_REMOVE` 均向被请出端发送 `6606`，其他与会者收到 `6605`。`6652` 只保留兼容解析，不作为当前流程的验收条件。

**通用工具**：
- `client.events.snapshot(deque名)` —— 线程安全拷贝当前事件（断言用）
- `client.events.clear()` —— 清空所有事件（分段断言用）
- `client.events.wait_until(predicate, timeout)` —— 任意条件等待
- `wait_for(predicate, timeout)`（`fm_client.testing` 顶层）—— 通用轮询

**typed 对象**：

| 类型 | 字段 |
|---|---|
| `Room` | `room_id:int` `name:str` `meeting_type:str|None` `raw:dict` |
| `Contact` | `user_id:int` `name:str` `mobile/tel/email:str` `dept_id:int|None` `raw:dict` |
| `UserEnter` | `user_id:int` `name:str` `right:int`(1旁听/2出席/3主席) `raw:dict` |
| `ChatMsg` | `src_user_id:int` `dst_user_id:int` `text:str` `msg_id:str|None` |

> 每个 typed 对象都带 `.raw`（原始字段 dict），需要拿非标准字段时兜底。

## 六、错误处理

- 请求-回复型命令，回复 `Result != 0` 默认抛 `fm_client.FmError(code)`。
- 用错误码断言：`with pytest.raises(FmError) as e: ...; assert e.value.code == 0x2101`。
- 想**即便失败也拿到回复字段**（如从 ROOMLIST 的 0x1002 里取 RoomNodeID）：底层 `_request(raise_on_error=False)`，或直接用 `front_discover_node()`（已封装）。
- 常见码：`0x2101` 密码错、`0x2102` 房间未找到、`0x2109` 需房间密码、`0x1002` 服务端异常（多为 DB）、`0x211C` 预约会议未到时间。

| 状态 | 命令 |
|---|---|
| ✅ 支持 | 登录/入会/聊天/音视频/录制/锁房/踢人/静音；6503 离线成员、6513 视图、6504 敲门、6527 改名、6515 字幕、6516 发文件、6523 建分组 |
| ⚠️ 超时（handler 未实现） | 6528 组织架构、6530 申请操作权、6525 结束分组 |
| ❌ 发出后断开会话（服务器不认） | 6534 会议配置、6518 系统消息、6568 撤回消息 |
| ⚠️ 0x1002 | ROOMLIST（DB 存储过程损坏）→ demo 已容错 |

**重要**：给真机发**未实现**的 cmdid 会被断开会话。`FmTestClient`/demo 对单个动作失败已容错，不会整体崩溃。

## 八、写测试的套路（Cookbook）

**套路 1：发动作 → 等广播断言**
```python
client.mic_on()
assert client.wait_for_user_state(timeout=3)
```

**套路 2：等特定用户/内容**
```python
client.chat("hi", dst_user_id=2002)
assert client.wait_for_chat(text="hi", timeout=3)
assert client.wait_for_user_enter(user_id=2002, timeout=10)
```

**套路 3：负向测试（期待失败）**
```python
from fm_client import FmError
with pytest.raises(FmError) as exc:
    client.front_login("A7", "wrong-password", room_id=10000, room_node_id="396593")
assert exc.value.code == 0x2101   # PASSWORDERROR
```

**套路 4：分段断言（clear 隔离）**
```python
client.wait_for_user_enter(timeout=3)   # 收初始成员
client.events.clear()                   # 清空
client.kick_user(2002)                  # 触发新事件
assert client.wait_for_user_leave(user_id=2002, timeout=3)
```

**套路 5：typed 列表断言**
```python
client.front_authenticate("A7", "<configure-locally>")
rooms = client.list_rooms()
assert {r.meeting_type for r in rooms} >= {"fixed", "reserved", "instant"}
assert all(isinstance(r.room_id, int) for r in rooms)
```

**套路 6：多模拟端——验证广播送达其他与会者**（A 驱动 + B 观察，8 步流程）
```python
a = FmTestClient(host, port); a.front_login("userA","pwd", room_id=R, room_node_id=N); a.conf_login()
b = FmTestClient(host, port); b.front_login("userB","pwd", room_id=R, room_node_id=N); b.conf_login()  # 不同账号
a_uid = a.room_user_id_int; b_uid = b.room_user_id_int
a.events.clear(); b.events.clear()                 # 步骤3

a.mic_on()                                         # 步骤4：A 发命令
assert a.wait_for_user_state(user_id=a_uid, timeout=3)   # 步骤7：A 自己收到回声
b_states = b.wait_for_user_state(user_id=a_uid, timeout=3)  # 步骤8：B 也收到
assert b_states and b_states[-1].get("Audio",{}).get("State") == "2"

a.kick_user(b_uid)                                 # A 踢 B
assert b.events.wait_for_kicked(user_id=b_uid, timeout=3)   # B 收到被踢推送
```

> 流程：①A 登录 Front ②A 登录 Conf ③clear ④A 发命令 ⑤服务器回复+广播 ⑥两端 EventCollector 收 ⑦A 断言自己收到 ⑧**断言 B 也收到**。
> mock 已支持多端广播（同房间多客户端 fan-out），所以这套流程**离线/CI 也能跑**（见 `tests/test_multi_client.py`）；真机把两个 `FmTestClient` 用两个不同账号连同一房间即可。

**多账号 JSON 配置**（省去手写两套登录参数）：编辑 `examples/multi_client.json` 填两个账号，然后
```python
from fm_client.testing import load_config, connect_pair
a, b = connect_pair(load_config("examples/multi_client.json"))   # 操作端 A + 观察端 B，已登录入会
```
其中 `conf_protocol_version` 会同时应用到两端的 `6501` 登录及后续全部 Conf 命令，
`initialization_wait`控制双端入会后的初始化稳定等待，`case_params`保存系统消息 ID 和
媒体辅流分享 ID 等真实环境参数。
默认值为 `1.2`；验证 `6530/6630` 操作权时应配置为 `2.0` 或更高版本。该配置不改变
Front 协议版本，也不会使服务器中未实现的 `6528` handler 自动可用。

或一键脚本：`python3 examples/fm_two_clients.py examples/multi_client.json`

## 十、方案 §4「待开发补齐接口」落地情况

13 个接口已全部处理（`MeetingControlOps`，`ops/meeting_control_ops.py`）。真实存在的用信令实现；信令里没有的抛 `ProtocolNotInSignaling` 并注明真实通道，避免测试侧误判：

| 接口 | 落地 | 命令 / 通道 |
|---|---|---|
| `set_user_audio(uid, state)` | ✅ 信令 | 6509 Audio → 6609（dev_id=0） |
| `set_user_video(uid, state)` | ✅ 信令 | 6509 Video → 6609 |
| `set_layout(type, user_ids, target_user_ids)` | ✅ 信令 | 6513 WNDSTATE(+DstInfo 定向) → 6613 |
| `set_role(uid, role, enabled)` | ✅ 信令 | presenter/admin：6509 DataState/ManagerState → 6609；chairman：6511(仅自申请) |
| `start_aux_stream()` / `stop_aux_stream()` | ✅ 信令 | media 开始必须带两个分享 ID、停止清零；VNC 使用 2/0 → 6609 |
| `configure_polling(...)` | ✅ 信令 | 6533 → **6633**（新下行，`on_video_polling`/`wait_for_polling`） |
| `invite_terminals(sns_list)` | ✅ 信令 | 6741 MAKECALL CallType=2 → 6745 |
| `invite_users(uids)` | ✅ HTTP(需 attach) | Web API `POST /v1/control/{roomId}` `operate=INVITE_USER` |
| `invite_contacts(uids)` | ✅ HTTP(需 attach) | 同 invite_users（通讯录号→uid 在客户端解析） |
| `create_reserved_meeting(...)` | ✅ HTTP(需 attach) | Web API `addRoomInfo` + `reservation` |
| `create_instant_meeting(...)` | ✅ HTTP(需 attach) | Web API `POST /v1/room/createInstant` |
| `cancel_reserved_meeting(...)` | ✅ HTTP(需 attach) | Web API `editRoomStatus(status=0)` / `delRoomInfo` |
| `lock_layout(enabled)` | ✅ HTTP(需 attach) | Web API `POST /v1/control/{roomId}` `operate=LOCK_LAYOUT` |

> 这些能力在 4u 终端信令里**没有**，统一封装在 `WebApiClient`（`fm_client/http_api.py`，仅 stdlib urllib）。
> 用法：`client.attach_http("http_api.json")` 后，`client.create_instant_meeting(...)` / `invite_users(...)` / `lock_layout(...)` 等自动走 HTTP；**未 attach 则抛 `ProtocolNotInSignaling`**（带 `channel` 字段指明真实通道），不会把"没这个命令"误当"发送成功"。
> 鉴权：JWT 自签 token = `base64({"alg":"SHA256"}).base64({ "key":<appKey>,"timestamp":<ms>}).SHA256(header+payload+secret)`，10 分钟有效（`WebApiClient` 自动刷新）。配置 `base_url/app_key/app_secret/verify_tls` 写 JSON（见 `examples/http_api.json`，或作 `multi_client.json` 的 `"http"` 子节）。
> `WebApiClient` 现已覆盖 `docs/api.html` 的部门、用户、会议室管理、录制纪要查询/导出、会控操作、拉流和订阅接口。
> 会议纪要/转写导出使用 `download_*()` / `export_*()` 返回原始字节；`request()`、`request_bytes()`、
> `control(room_id, operate, param)` 仍可用于服务端扩展字段或新增操作。

统一下行事件 `ReceivedEvent` 保留 `source/cmdid/name/fields/raw_xml/received_at`，并增加
`event_id/kind/seq/request_cmdid/received_monotonic/decode_error/raw_payload`。每条服务器下行
（回复、推送、未知消息和解析失败）都记入 `EventCollector.received`；测试可用
`mark()` + `wait_event(after=...)` 隔离历史事件，或继续使用兼容接口
`wait_for_cmdid(cmdid, timeout)`，便于按请求关联断言和在 Allure 中展示脱敏后的原始 XML。
最新版 `ConfProtocol.xml` 中已知的主动下行均注册到 `PUSHES`，因此会以 `kind="notify"`
进入统一事件，而不是退化成 `unknown`。

## 十一、一页速记

- **入口**：`from fm_client import FmTestClient, FmError`；mock 测试用 `fm` fixture。
- **入会三连**：`front_login(...)` → `conf_login(...)` → 做动作。
- **等推送**：`client.wait_for_xxx(timeout=)`，别手写轮询。
- **类型**：用 typed 对象的 int 字段，别直接比 raw dict 里的字符串。
- **错误**：`FmError(code)`，`0x` 开头的码。
- **真机**：先 `--discover-node` 取 RoomNodeID；不支持的命令会被断开会话（已容错）。
