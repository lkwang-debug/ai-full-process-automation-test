# sessionmanager_py 测试框架调用设计

## 1. 设计目标

开发侧交付 `FmTestClient`、公开业务接口和统一下行事件对象；测试侧可按自己的 pytest、
Excel 或报告体系，在 `FmTestClient` 之上增加 `MeetingTestRuntime`，统一管理一个测试场景中的
多个模拟会议客户端。本文中的 Runtime 是测试侧参考实现，不属于 `sessionmanager_py` SDK 的
必需交付物。

```text
pytest / Excel测试步骤
        |
MeetingTestRuntime
        |
多个FmTestClient（operator、observer、target等）
        |
真实会议服务器
```

这一层主要解决以下问题：

- 使用别名管理多个客户端，测试用例不直接保存底层连接对象。
- 统一完成 Front 登录、Conf 登录和会议初始化。
- 将 Excel 中的操作名称映射到允许调用的业务方法。
- 统一清理历史事件、等待服务器通知和匹配协议字段。
- 在测试结束后关闭所有连接，避免连接和用户状态残留。

其中：

- `operator`：操作端A，负责发送会议业务命令。
- `observer`：观察端B，负责接收服务器广播并执行主要断言。
- `target`：可选目标端，用于请出、角色控制、指定用户音视频等场景。

## 2. MeetingTestRuntime 测试侧参考实现

```python
import time
from typing import Any, Dict, Optional

from fm_client import FmTestClient


class MeetingTestRuntime:
    """管理单条测试场景中的多个模拟会议客户端。

    Runtime只负责测试编排，不负责实现会议协议。具体协议仍由
    FmTestClient和它内部的FrontOps、ConfOps等业务封装完成。
    """

    # Excel和pytest使用统一的事件名称，Runtime负责映射到
    # EventCollector中实际保存事件的deque队列。
    EVENT_QUEUES = {
        "USER_ENTER": "user_enters",                 # 成员入会
        "USER_LEAVE": "user_leaves",                 # 成员离会
        "USER_STATE_CHANGED": "user_states",         # 音视频、权限等用户状态变化
        "USER_KICKED": "kicks",                      # 用户被请出
        "ROOM_CLOSED": "room_closes",                # 会议关闭
        "CONF_STATE_CHANGED": "conf_states",         # 录制、锁定等会议状态变化
        "SILENT_NOTIFY": "silents",                  # 全体静音通知
        "SUBTITLE_NOTIFY": "subtitles",              # 字幕通知
        "WINDOW_STATE_NOTIFY": "window_states",      # 窗口或视图状态通知
        "ROLE_PERMISSION_NOTIFY": "role_perms",      # 角色权限通知
        "CALL_STATE_NOTIFY": "call_states",          # 电话/H323呼叫状态
    }

    def __init__(
        self,
        host: str,
        port: int,
        room_node_id: str,
        request_timeout: float = 10,
    ):
        # host和port是Fm服务接入地址，不是真实终端地址。
        self.host = host
        self.port = int(port)

        # room_node_id是Front进入房间时需要的节点标识。
        self.room_node_id = str(room_node_id)
        self.request_timeout = float(request_timeout)

        # alias -> FmTestClient，例如operator -> 客户端A。
        self.clients: Dict[str, FmTestClient] = {}

        # alias -> 账号配置。账号和客户端分开保存，方便join时读取。
        self.accounts: Dict[str, dict] = {}

        # 保存运行过程中产生的用户ID、会议ID等变量，供后续步骤引用。
        self.variables: Dict[str, Any] = {}

    def create_client(self, alias: str, account: dict) -> FmTestClient:
        """创建一个模拟客户端实例，但暂不登录会议。

        alias是测试中的逻辑名称，例如operator或observer。
        account至少包含username和password。
        """
        if not alias:
            raise ValueError("客户端alias不能为空")
        if alias in self.clients:
            raise ValueError(f"客户端别名已存在: {alias}")
        if not isinstance(account, dict):
            raise TypeError("account必须是字典")
        if not account.get("username"):
            raise ValueError(f"客户端{alias}缺少username")
        if "password" not in account:
            raise ValueError(f"客户端{alias}缺少password")

        # 实例化对象时只创建客户端及EventCollector。
        # Front/Conf连接会在join()中按需建立。
        client = FmTestClient(
            self.host,
            self.port,
            request_timeout=self.request_timeout,
        )

        self.clients[alias] = client
        self.accounts[alias] = dict(account)
        return client

    def join(self, alias: str, roomid: int) -> dict:
        """让指定客户端完成Front登录和Conf登录。

        执行顺序：
        1. front_login：用户认证并进入房间，获取Token和Conf地址。
        2. conf_login：使用Token登录会议，并发送初始化完成消息。
        3. 保存后续断言需要使用的运行变量。
        """
        client = self._get_client(alias)
        account = self.accounts[alias]

        # front_login内部会连续执行USERLOGIN和LOGINROOM。
        front_response = client.front_login(
            account["username"],
            account["password"],
            room_id=int(roomid),
            room_node_id=account.get("room_node_id", self.room_node_id),
            room_password=account.get("room_password"),
            token=account.get("token"),
            user_type=account.get("user_type", 1),
            terminal_type=account.get("terminal_type", 1),
            client_type=account.get("client_type", 1),
        )

        # conf_login成功后，该客户端才是完整的会内成员。
        # init_complete默认为True，会自动发送初始化完成消息。
        conf_response = client.conf_login(
            user_name=account.get("display_name", account["username"]),
        )

        # 保存运行变量，Excel中可通过${operator.room_user_id}等形式引用。
        self.variables[f"{alias}.local_user_id"] = client.local_user_id_int
        self.variables[f"{alias}.room_user_id"] = client.room_user_id_int
        self.variables[f"{alias}.room_id"] = client.room_id
        self.variables[f"{alias}.user_right"] = client.user_right_int

        return {
            "front": front_response,
            "conf": conf_response,
        }

    def call(
        self,
        alias: str,
        operation: str,
        params: Optional[dict] = None,
    ):
        """在指定客户端上执行一个允许的会议业务操作。

        Excel只传operation名称，不允许直接反射调用任意Python方法。
        新增协议能力后，只需要在此白名单注册对应方法。
        """
        client = self._get_client(alias)
        params = params or {}

        if not isinstance(params, dict):
            raise TypeError("params必须是字典")

        # 当前sessionmanager_py已经封装的主要业务操作。
        operations = {
            "mic_on": client.mic_on,                         # 打开本端麦克风
            "mic_off": client.mic_off,                       # 关闭本端麦克风
            "mic_request": client.mic_request,               # 申请发言
            "camera_on": client.camera_on,                   # 打开本端摄像头
            "camera_off": client.camera_off,                 # 关闭本端摄像头
            "start_record": client.start_record,             # 开始录制
            "pause_record": client.pause_record,             # 暂停录制
            "stop_record": client.stop_record,               # 停止录制
            "lock_room": client.lock_room,                   # 锁定会议
            "unlock_room": client.unlock_room,               # 解锁会议
            "mute_all": client.mute_all,                     # 全体静音
            "set_subtitle": client.set_subtitle,             # 设置字幕
            "close_subtitle": client.close_subtitle,         # 关闭字幕
            "kick_user": client.kick_user,                   # 请出用户
            "close_room": client.close_room,                 # 关闭会议
            "apply_host": client.apply_host,                 # 申请主持人
            "release_host": client.release_host,             # 释放主持人
            "set_window_state": client.set_window_state,     # 上报窗口状态
            "conf_logout": client.conf_logout,               # 退出Conf会议
        }

        method = operations.get(operation)
        if method is None:
            raise ValueError(f"未注册的会议操作: {operation}")

        # params按关键字参数传入。例如：
        # operation=set_subtitle, params={"data": "测试字幕"}
        return method(**params)

    def clear_events(self, alias: str) -> None:
        """清空指定客户端EventCollector中的历史业务事件。

        A、B都登录完成后应执行一次，避免初始化阶段的成员和状态通知
        被后续业务断言误匹配。
        """
        self._get_client(alias).events.clear()

    def wait_event(
        self,
        alias: str,
        event: str,
        match: Optional[dict] = None,
        timeout: float = 10,
    ):
        """等待指定客户端收到满足条件的服务器事件。

        event是统一事件名，例如USER_STATE_CHANGED。
        match使用点路径匹配嵌套字段，例如Audio.State。
        XML可重复节点只有一个时会解析成对象；匹配器将其视为索引0，
        因此DataItem.0.ItemID可同时匹配单对象和列表两种下行形态。
        成功时返回匹配到的事件，超时时抛出AssertionError。
        """
        client = self._get_client(alias)
        queue_name = self.EVENT_QUEUES.get(event)

        if queue_name is None:
            raise ValueError(f"未注册的事件类型: {event}")

        queue = getattr(client.events, queue_name)
        match = match or {}

        def find_event():
            # snapshot()在线程锁保护下复制事件，避免接收线程并发修改deque。
            for item in client.events.snapshot(queue):
                if self._matches(item, match):
                    return item
            return None

        deadline = time.monotonic() + float(timeout)
        while time.monotonic() < deadline:
            matched = find_event()
            if matched is not None:
                return matched
            time.sleep(0.05)

        # 超时时输出实际收到的事件，便于在pytest/Allure中定位字段差异。
        received = client.events.snapshot(queue)
        raise AssertionError(
            f"客户端{alias}等待事件超时: "
            f"event={event}, match={match}, received={received}"
        )

    def close_all(self) -> None:
        """关闭当前测试场景中的全部客户端连接。

        单个客户端关闭失败不会阻止其他客户端继续清理。
        """
        for alias, client in reversed(list(self.clients.items())):
            try:
                client.close()
            except Exception as exc:
                # 实际测试框架中应改为日志和Allure附件。
                print(f"关闭客户端失败: alias={alias}, error={exc}")

        self.clients.clear()
        self.accounts.clear()
        self.variables.clear()

    def _get_client(self, alias: str) -> FmTestClient:
        """根据别名获取客户端，不存在时给出明确错误。"""
        try:
            return self.clients[alias]
        except KeyError as exc:
            raise KeyError(f"客户端不存在: {alias}") from exc

    @classmethod
    def _matches(cls, event: Any, expected: dict) -> bool:
        """判断事件中的字段是否满足全部预期条件。"""
        for path, expected_value in expected.items():
            actual_value = cls._read_path(event, path)

            # XML解析后的数值可能是字符串，第一版统一转换为字符串比较。
            # 后续可扩展contains、exists、正则和数值比较。
            if str(actual_value) != str(expected_value):
                return False
        return True

    @staticmethod
    def _read_path(value: Any, path: str):
        """读取字典或typed事件中的点路径字段。"""
        current = value
        for key in path.split("."):
            if isinstance(current, dict):
                current = current.get(key)
            elif hasattr(current, key):
                current = getattr(current, key)
            else:
                return None
        return current
```

## 4. A、B登录会议

```python
room_id = 10000

# A完成Front认证、进入房间和Conf登录。
operator_login = runtime.join("operator", room_id)

# B进入同一个会议室，作为服务器广播的观察端。
observer_login = runtime.join("observer", room_id)
```

`join()`内部执行：

```text
front_login()
-> USERLOGIN用户认证
-> LOGINROOM进入房间
-> 获取RoomUserID、Token和Conf地址
-> conf_login()
-> 使用Token登录会议
-> 发送初始化完成消息
```

两个客户端都完成初始化后，清除登录阶段收到的成员和状态事件：

```python
runtime.clear_events("operator")
runtime.clear_events("observer")
```

## 5. 执行会中操作并验证广播

以“A打开麦克风，B验证服务器广播”为例。

### 5.1 A发送业务命令

```python
runtime.call(
    alias="operator",
    operation="mic_on",
    params={},                       # mic_on不需要额外参数
)
```

实际调用链：

```text
runtime.call("operator", "mic_on", {})
-> 获取operator对应的FmTestClient
-> 调用operator.mic_on()
-> 向服务器发送改变用户状态协议
```

### 5.2 B等待服务器通知

```python
event = runtime.wait_event(
    alias="observer",
    event="USER_STATE_CHANGED",
    match={
        # 必须匹配A在会议中的RoomUserID，避免误匹配其他成员事件。
        "UserID": runtime.variables["operator.room_user_id"],

        # Audio.State=2表示当前协议定义中的发言/开麦状态。
        "Audio.State": 2,
    },
    timeout=10,
)

assert event is not None
```

完整闭环：

```text
A执行mic_on
-> 会议服务器接收并处理
-> 服务器广播USERSTATECHANGED
-> B的FmTestClient接收XML
-> EventCollector保存到user_states
-> wait_event匹配UserID和Audio.State
-> pytest断言通过
```

## 6. pytest完整用例

推荐使用fixture统一创建、登录和清理客户端。

```python
import os

import pytest


@pytest.fixture
def meeting_runtime():
    """为每条测试用例准备A、B两个已入会客户端。"""
    runtime = MeetingTestRuntime(
        host=os.environ["FM_HOST"],
        port=int(os.environ.get("FM_PORT", "1089")),
        room_node_id=os.environ["FM_ROOM_NODE_ID"],
        request_timeout=10,
    )

    runtime.create_client(
        "operator",
        {
            "username": os.environ["FM_OPERATOR_USER"],
            "password": os.environ["FM_OPERATOR_PASSWORD"],
            "display_name": "操作端A",
        },
    )

    runtime.create_client(
        "observer",
        {
            "username": os.environ["FM_OBSERVER_USER"],
            "password": os.environ["FM_OBSERVER_PASSWORD"],
            "display_name": "观察端B",
        },
    )

    try:
        room_id = int(os.environ["FM_ROOM_ID"])

        runtime.join("operator", room_id)
        runtime.join("observer", room_id)

        # 清除登录初始化阶段的事件，只保留用例操作之后的新事件。
        runtime.clear_events("operator")
        runtime.clear_events("observer")

        yield runtime
    finally:
        # 无论测试通过还是失败，都关闭全部会话。
        runtime.close_all()


def test_operator_mic_on_is_broadcast_to_observer(meeting_runtime):
    """验证A打开麦克风后，B收到正确的用户状态通知。"""
    runtime = meeting_runtime

    runtime.call("operator", "mic_on", {})

    event = runtime.wait_event(
        "observer",
        "USER_STATE_CHANGED",
        {
            "UserID": runtime.variables["operator.room_user_id"],
            "Audio.State": 2,
        },
        timeout=10,
    )

    assert event is not None
```

## 7. Excel数据转换为Runtime调用

Excel只描述业务步骤，不保存Python客户端对象。

示例数据：

| 操作端 | 动作 | 参数 | 接收端 | 预期事件 | 匹配字段 |
|---|---|---|---|---|---|
| operator | mic_on | `{}` | observer | USER_STATE_CHANGED | `{"UserID":"${operator.room_user_id}","Audio.State":2}` |

场景执行器读取Excel并替换变量后，转换为：

```python
# 执行业务动作
runtime.call(
    alias="operator",
    operation="mic_on",
    params={},
)

# 等待并断言观察端收到服务器广播
runtime.wait_event(
    alias="observer",
    event="USER_STATE_CHANGED",
    match={
        "UserID": runtime.variables["operator.room_user_id"],
        "Audio.State": 2,
    },
    timeout=10,
)
```

推荐由Excel执行器按以下顺序调用Runtime：

```text
create_client(operator)
create_client(observer)
join(operator, room_id)
join(observer, room_id)
clear_events(operator)
clear_events(observer)
call(operator, mic_on, {})
wait_event(observer, USER_STATE_CHANGED, {...}, 10)
close_all()
```

## 8. 当前可接入的会议控制能力

布局、角色、邀请、辅流和轮询接口均已由开发侧封装在 `FmTestClient` 中。测试框架如需
通过动作名调用，只需将这些公开接口注册到自己的 `call()` 白名单；不需要测试人员构造
底层 XML：

```python
operations = {
    # 核心会中操作
    "mic_on": client.mic_on,
    "set_user_audio": client.set_user_audio,           # 控制指定用户音频
    "set_user_video": client.set_user_video,           # 控制指定用户视频
    "set_layout": client.set_layout,                   # 设置布局
    "set_role": client.set_role,                       # 设置用户角色
    "set_role_permissions": client.set_role_permissions,  # 修改角色功能权限
    "set_user_permissions": client.set_user_permissions,  # 修改指定用户功能权限
    "set_room_data": client.set_room_data,               # 设置会场/课堂数据
    "get_av_mix_params": client.get_av_mix_params,       # 查询AV合成参数
    "set_av_mix_params": client.set_av_mix_params,       # 设置AV合成参数
    "set_video_subtitle_params": client.set_video_subtitle_params,  # 视频字幕参数
    "invite_users": client.invite_users,               # 邀请普通用户
    "invite_terminals": client.invite_terminals,       # 邀请SNS终端
    "start_aux_stream": client.start_aux_stream,       # 开始辅流
    "stop_aux_stream": client.stop_aux_stream,         # 停止辅流
    "configure_polling": client.configure_polling,     # 配置视频轮询
    "request_right": client.request_right,             # 申请排他操作权
    "release_right": client.release_right,             # 释放排他操作权
}
```

接口通道和验证事件：

| 接口 | 通道 | 主要下行验证 |
|---|---|---|
| `set_user_audio` / `set_user_video` | Conf 6509 | 6609 `USERSTATECHANGED` |
| `set_layout` | Conf 6513 | 先申请 `RIGHT_TYPE_LAYOUT`；6613 `WNDSTATENOTIFY` |
| `set_role` | Conf 6509/6511 | 6609/6611；chairman 仅支持本端申请/释放 |
| `set_role_permissions` | Conf 6532 | 6632 `ROLEPERMISSIONCHANGED` |
| `set_user_permissions` | Conf 6535 | 6635 `USERPERMISSIONCHANGED` |
| `set_room_data` | Conf 6519 | 6619 `ROOMDATANOTIFY` |
| `get_av_mix_params` / `set_av_mix_params` | Conf 6520/6521 | 查询返回 6620；设置无直接回复，应回读确认 |
| `set_video_subtitle_params` | Conf 6522 | 6622 `VIDEOSUBTITLENOTIFY` |
| `invite_users` | Web HTTP | 需先 `attach_http()`；参数是平台用户 ID |
| `invite_terminals` | Conf 6741 | 6742 Response + 6745 `CALLSTATE_NOTIFY` |
| `start_aux_stream` / `stop_aux_stream` | Conf 6509 | media/VNC 分别申请 `RIGHT_TYPE_MEDIA_SHARE`/`RIGHT_TYPE_SCREEN_SHARE`；6609 Notify |
| `configure_polling` | Conf 6533 | 先申请 `RIGHT_TYPE_VIDEO_POLLING`；6633 视频轮询 Notify |

布局、辅流和轮询不能只发送业务命令。测试步骤应显式表达操作权的生命周期，例如：

```python
from fm_client import conf as C

client.request_right(C.RIGHT_TYPE_LAYOUT)
try:
    client.set_layout(
        layout_type=1001,
        user_ids=[operator_uid, observer_uid],
        target_user_ids=[observer_uid],
    )
finally:
    client.release_right(C.RIGHT_TYPE_LAYOUT)
```

`request_right()` 会等待 6630 Response；`Result != 0` 会直接抛出 `FmError`。其中
`0x211E RIGHTOCCUPIED` 表示该排他权正在被其他用户占用。测试代码应在 `finally` 中释放权利，
避免后续用例相互污染。

角色权限和指定用户权限是通知型操作，测试应由观察端验证 6632/6635：

```python
mark = observer.events.mark()
operator.set_role_permissions(
    ["mentee", "audit"],
    operate_public_chat=False,
    operate_private_chat=True,
    permissions={"ConfigChatCheck": 1},
)
assert observer.events.wait_event(
    after=mark,
    source="conf",
    cmdid=6632,
    kind="notify",
    match={"RoleCode": "mentee", "OperatePublicChat": 0},
    timeout=10,
)

mark = observer.events.mark()
operator.set_user_permissions(
    observer.room_user_id_int,
    operate_public_chat=True,
    operate_private_chat=False,
)
assert observer.events.wait_event(
    after=mark,
    source="conf",
    cmdid=6635,
    kind="notify",
    match={"UserID": observer.room_user_id_int, "OperatePrivateChat": 0},
    timeout=10,
)
```

`set_role()` 修改的是某个用户的主讲/管理员/主持人状态；`set_role_permissions()` 修改的是
整个角色类别的功能权限。两者不是同一协议，也不应在测试动作中互换。

AV 合成参数的设置没有直接回复，自动化测试应设置后回读：

```python
audio = C.ConfCmd.av_mix_audio(fec_type=1, encoder_id=6)
video = C.ConfCmd.av_mix_video(
    width=1280,
    height=720,
    frame_rate=25,
    encoder_id=3,
    encoder_mode=1,
    bitrate=2048,
    vbr_quality=60,
    key_frame_interval=50,
)
operator.set_av_mix_params(
    enable_default=False,
    audio=audio,
    video=video,
)
actual = operator.get_av_mix_params()
assert actual["Video"]["Width"] == "1280"
```

`set_subtitle()` 对应 6515 会场文字字幕；`set_video_subtitle_params()` 对应 6522
视频画面上的日期时间/用户名样式，两者语义不同。服务器录制异常 6636 可通过
`client.wait_for_server_record_error(error=None, timeout=...)` 等待。

所有合法下行都会进入统一的 `EventCollector.received`，因此测试框架可以直接使用
`mark()` + `wait_event()` 按 source、kind、cmdid 和 fields 断言，不再要求每个新 Notify
都增加独立的 `EVENT_QUEUES` 映射。最新版 `ConfProtocol.xml` 中已知的服务端主动消息均已
注册为 `kind="notify"`；6618/6624/6626/6650 在发送端仍按 Response 关联，在其他客户端按
Notify 分发。专用 typed 队列继续作为便捷接口保留。

## 9. 实施注意事项

- A、B必须使用不同账号并加入同一会议。
- 主持操作需要A具备对应权限。
- 两端登录完成后再清空事件，防止初始化消息误匹配。
- 事件断言必须同时匹配事件类型、目标用户ID和核心状态字段。
- 不能用`call()`未抛异常代替B收到服务器广播的断言。
- 踢人、关会等破坏性用例应使用独立会议。
- fixture必须在`finally`中调用`close_all()`。
- 当前第一版字段比较会统一转换成字符串；后续可扩展类型、包含、存在性和正则断言。
- 已提供统一 `ReceivedEvent`；`wait_event()` 应使用 `mark()` 产生的事件游标，优先按
  source、kind、cmdid、fields 和 request_cmdid 匹配，避免历史事件误命中。
